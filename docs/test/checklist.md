# 실기 테스트 체크리스트 (Test Checklist)

작성 및 검토: @claude, @skim

scenarios.md의 실행 안내서이다. 각 항목의 상세 절차와 확인 기준은 시나리오 ID(M-xx, W-xx)로 원문을 참조하고, 이 문서는 진행 순서, 담당 구분, 시간 배치만 다룬다. 항목을 마치면 체크하고, 실패하면 하단의 결함 기록에 남긴다.

**메시지 응답 규칙** — 항목 아래의 대화는 항목 바로 밑의 코드 블록에 기록한다. 사용자가 `@skim:`으로 메시지를 남기면, 클로드는 같은 블록에 `@claude:`로 시작하는 의견을 덧붙인다.

작성 형식은 다음과 같다.
- 메시지는 `@skim:` 또는 `@claude:`로 시작하고, 메시지 사이는 빈 줄로 구분한다.
- 절차·관찰처럼 여러 줄이 필요한 내용은 요지 문장("아래와 같이 …") 뒤에 `---`로 감싼 목록으로 적는다. 한 문장이면 `---` 없이 적는다.
- 같은 화자가 나중에 덧붙일 때는 새 메시지로 추가한다. (예: `@claude: (추가) …`)

메시지의 의미는 체크 상태에 따라 다음과 같다.
- 체크됨 + 메시지: 확인해 볼 부분이 있을 수 있다는 알림이다. 검토 후 의견을 남긴다.
- 체크 안 됨 + 메시지: 실행 중 발생한 문제 또는 방법에 대한 질문이다. 결함인지 무해한 것인지 판별하고, 즉시 해결할 수 있는 것은 해결한 뒤 결과를 남긴다.
- 체크 안 됨 + 메시지 없음: 진행이 끝난 구간에서는 비정상이다. 사용자가 놓쳤을 수 있으므로 클로드가 발견 즉시 지적한다.
  
담당 구분은 세 가지로 표기한다.
- **[직접]** 육안 확인이나 물리 조작이 필요하여 사용자가 직접 수행한다.
- **[브라우저]** 실제 브라우저 조작이 필요하다. 직접 수행하거나 B(PC)의 클로드에게 맡긴다.
- **[위임]** API 호출과 로그 확인으로 끝나므로 A(Jetson)의 클로드에게 맡길 수 있다.
