# 5. 성능 요구사항 (Performance Requirements)

본 장의 성능 요구사항은 권장 사양(AGX Orin 64 GB, §3.1 (1))을 기준 환경으로 한다. 실측이 모두 이 환경에서 이루어졌고 최소 사양 장비는 확보하지 않았기 때문이다(§3.5). 수치 목표는 정의하지 않는다 — 소수 운영자·단일 카메라 전제에서 수치 목표가 설계를 바꾸지 않으며, 검증 수단(벤치마크·부하 시험)이 소규모 프로젝트의 범위를 넘기 때문이다. 각 항목은 요구의 방향과 종속 관계만 정한다.

## 5.1 작업 처리량 (Throughput)

- `NFR-001` 시스템은 ***Video source*** 1개의 H.264 비디오 스트림을 끊김 없이 실시간으로 수신하고 디코딩해야 한다. 지원하는 최대 해상도와 프레임레이트는 정의하지 않는다.
- `NFR-002` 시스템은 VLM 추론을 연속적으로 수행해야 한다. 최소 추론 처리량은 정의하지 않는다.

## 5.2 동시 세션 (Concurrent Session)

- `NFR-003` 시스템은 복수의 동시 라이브 스트리밍 세션(HLS/WebRTC 합산)을 지원해야 한다. 최소 세션 수는 정의하지 않는다.
- API 동시 요청에 대한 요구사항은 두지 않는다. 시스템은 소수 운영자의 사용을 전제한다.

## 5.3 대응 시간 (Response Time)

대응 시간이 특히 중요한 항목만 정의한다.

- `NFR-004` 이벤트 감지 지연: 이벤트 상황 발생부터 이벤트 인지(키워드 매칭)까지의 지연은 VLM 추론 주기에 종속된다. 허용 상한은 정의하지 않는다.
- `NFR-005` 라이브 스트리밍 지연: WebRTC 및 HLS의 허용 지연은 정의하지 않는다.
- `NFR-006` 시스템 기동 시간: 모델 캐시가 존재하는 상태(웜 부트)에서 기동 완료까지의 허용 시간은 정의하지 않는다. 최초 부팅의 모델 컴파일 시간은 기동 시간에 포함하지 않는다.
- `NFR-007` PTZ 명령 반영 지연: 사용자 입력부터 카메라 동작까지의 허용 지연은 정의하지 않는다.

## 5.4 성능 종속관계 (Performance Dependency)

- 이벤트 감지 지연(`NFR-004`)은 VLM 추론 주기에 비례한다. 추론 주기는 하드웨어 등급에 종속된다 — 기준 환경(AGX Orin)에서 VILA1.5-3b의 추론 1회는 약 1.7초로 관측되었다(`docs/test/checklist.md` M-34). 최소 사양(Orin NX)의 값은 측정하지 않았다.
- 추론 주기가 짧아지면(고성능 하드웨어) 연속 추론 간 입력 프레임의 변화량이 줄어들어, 프레임 윈도 설정(추출 주기·추론당 프레임 수)의 조정이 필요할 수 있다.
- 생성 토큰 상한을 늘리면 장면 설명이 길어져 키워드 매칭 기회가 늘어나는 대신 추론 시간이 길어진다.
- 동시 스트리밍 세션 수와 VLM 추론 성능의 상호 영향은 측정하지 않았다.

## 5.5 그 외 성능 요구사항 (Other Performance Requirements)

- `NFR-008` 이벤트 감지 품질: 감지 정확도(precision)와 재현율(recall)의 목표치는 정의하지 않는다. 감지 품질은 VLM과 프롬프트에 종속되어 시스템이 보장할 수 없는 속성이며(`NFR-009`), 측정에는 대체 소스를 이용한 입력 재현을 활용한다.
