# 미결 사항 (Open Issues)

이 문서는 SRS 본문에 남아 있는 미결 사항을 기록한다. 각 항목은 프로토타입의 설계 및 구현 단계에서 결정하며, 결정된 내용을 SRS에 반영한 뒤 이 문서를 삭제한다.

두 항목 모두 §2를 여섯 구성요소 체계로 개정하는 과정에서 드러났으며, 이름 표기만 새 체계에 맞추고 내용의 판단은 미루었다.

## (1) `NFR-019`의 주체

`NFR-019`는 ***Video streamer***의 기동 지연을 견뎌야 하는 주체를 ***Source controller***로 적고 있다. 이는 연계된 `FR-015`가 프로필을 적용하는 시점의 연결을 다루고 프로필이 ***Source controller***의 소관이라는 점을 근거로 삼은 잠정 배정이다.

다만 재배포된 스트림을 입력으로 받는 ***Video analyzer*** 역시 같은 지연에 노출된다. 주체가 둘 중 하나인지 아니면 양쪽 모두인지는 컴포넌트 사이의 호출 관계가 확정되어야 정할 수 있다.

## (2) §2와 어긋나는 서술

### 라이브 스트리밍 접근 통제

§2.3 (6)은 재생 요청 역시 ***Request router***를 경유하며 별도의 스트림 접근 토큰을 두지 않는 것으로 정하였다. ***Request router***를 통과한 요청은 정당한 것으로 간주되므로 목적지에서 다시 검증하지 않는다. 직접 전달되는 것은 WebRTC 비디오뿐이다.

반면 아래 서술은 ***Client app***이 토큰을 지니고 ***Video streamer***에 직접 접속하며 ***Video streamer***가 그 토큰을 검증하는 구조를 전제한다.

- §4 `IF-003` : ***Client app***이 발급받은 JWT로 ***Video streamer***에 직접 연결하고, ***Video streamer***가 이를 검증한다.
- §4.1 : ***Request router***로 통합할 대상을 정리한 표의 "스트림 접속 정보 발급(URL + JWT)" 항목.
- §7 `FR-021`·`FR-023` : 스트림 접근 토큰과 그 폐기 지연에 관한 서술.

어느 구조를 택할지는 저지연 요구와 접근 통제의 대가를 견주어 정한다. 결정한 뒤에는 §2와 위 서술 중 한쪽을 다른 쪽에 맞추어야 한다.

### 프로필 용어

§2와 §7.2는 "비디오 소스 프로필"로 적으나, §4는 다섯 곳에서 "카메라 프로필"로 적는다(`/camera` 엔드포인트 두 곳, `IF-002` 두 곳, `IF-004` 한 곳). 대상을 RTSP 카메라로 한정한 v1.0에서는 두 용어가 같은 것을 가리킨다.

이 용어 통일은 설계 결정을 기다릴 필요가 없는 사안이나, 위 접근 통제 결정에 따라 §4를 손보게 되므로 그때 함께 정리한다.
