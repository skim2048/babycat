Babycat 문서 교정 규범
======================

적용 대상은 docs/srs와 docs/sdd의 본문 산문이다. 절 제목, 표의 셀, 요구사항
식별자(FR-000 등), 코드·경로·프로토콜 표기는 대상이 아니다.

1. 태(態)
   - 행위 주체가 문장에 있거나 문맥상 자명하면 능동태로 쓴다.
     (예) "요청은 별도의 오류 없이 무시된다" → "요청을 별도의 오류 없이 무시한다"
   - 특정 행위자가 없는 상태 서술의 피동은 허용한다.
     (예) "라이브 스트리밍은 유지된다"

2. 금지·교체 어휘
   - "이루어지다"는 쓰지 않는다. 뜻에 맞는 동작 동사로 바꾼다.
   - 지시어 "해당"은 "그"로 바꾸거나 지운다. 동사 "해당하다"(부합하다)는 무방하다.
   - 경로·도구가 실질 주어인 문장은 "~를 통해"로 처리하지 않고 주어로 승격한다.
     (예) "파이프라인을 통해 생성된 텍스트" → "파이프라인이 생성한 텍스트"
     단순한 수단 표시(예: "Client app을 통해 요청할 때")는 허용한다.

3. 명사화와 조사 연쇄
   - "~했음을 …한다" 꼴은 동사문으로 푼다.
     (예) "접수했음을 즉시 응답하고" → "접수했다는 응답을 즉시 보내고"
   - "~의"가 이어지거나 동작을 명사 속에 감춘 곳은 동사문으로 푼다.
     (예) "PTZ 제어의 완료를 뜻하지는 않는다" → "PTZ 제어가 완료되었다는 뜻은 아니다"
   - "~와의", "~에의" 같은 겹조사는 풀어 쓴다.

4. 문체 층위
   - 관용 표현과 구어체를 쓰지 않는다.
     (예) "걸어두고", "잡히면", "훑어", "가져다 붙인다", "다룰 줄 안다", "쓸 만한지"
   - "~것"은 대체 표현이 있으면 피한다.

5. 정보 밀도
   - 절차문(전체 동작 방식)은 한 단계에 한 주어의 행위만 적는다. 판정에 따른
     분기는 하위 항목으로 둔다.
   - 기능 목록에는 기능만 적는다. 범위 한정의 근거는 단계별 요구사항(SRS §2.7)과
     기능 요구사항(SRS §7)이 맡는다.

6. 분기 표기
   - 한 판정에 따른 상보적 분기의 나열은 "조건 → 동작" 표기를 허용한다. 이 표기는
     완결 문장 규범의 예외다.
   - 조건은 명사형(-함/-음)으로 맺고, 조건의 결합은 기호 없이 말로 잇는다.
     (예: "자격증명이 정당하고 로그인 유지를 요청함")
   - 동작의 나열은 구분 기호 규칙을 따르고, 순서는 "후"로 잇는다.
     (예) 자격증명이 정당함 → 기존 로그인 세션 무효화 후 액세스 토큰 발급

기확정 표기 규칙 (이 규범과 함께 유지)
   - 장·절 참조는 § 기호로 표기한다(SRS §1.3 (3), SDD §1.3).
   - 구분 기호: /는 택일·대응, ·는 닫힌 나열(뒤에 "등"을 붙일 수 없음),
     ,는 열린 나열(뒤에 "등"을 붙일 수 있음).
   - 컴포넌트는 굵은 기울임(***Request router***), 컨테이너·서비스·코드
     식별자는 고정폭(`router`)으로 적는다(SDD §1.3).
